🔬 Scientific Reality: When Does MeruCode Compress?

Shannon's Source Coding Theorem establishes that no lossless algorithm can compress every input. Yukti provides an honest, measured account:

✓ When It Truly Compresses (35% – 54% Ratio)

Sparse & Dense Bitstreams (p ≈ 0.05 or 0.95), Run-Heavy Data, All Zeros:

Most blocks have few Gurus (k = 0 or 1). C(8, 0) = 1 (0 rank bits) and C(8, 1) = 8 (3 rank bits). Total per block is far smaller than 8 bits, yielding 45% to 65% size reduction.

✕ When It Only Encodes (Expands by ~15% – 30%)

Incompressible White Noise (p = 0.5) & Balanced ASCII Text ("saket"):

For balanced blocks (k ≈ 4), C(8, 4) = 70, requiring 7 rank bits + 4 k-bits = 11 bits/block. By the pigeonhole principle and Shannon's limit (H = 1.0), balanced noise provably expands.
